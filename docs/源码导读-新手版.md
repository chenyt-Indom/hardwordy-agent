# 第一部分 · 先补 5 个概念（10 分钟）

不补这 5 个，后面每一行你都会卡住。

## 1. 前端 / 后端

- **后端**（`backend/` 里的 Python）：真正干活的，管模型、管文件、管工具。
- **前端**（`frontend/` 里的 HTML/CSS/JS）：只负责"画界面"和"把你说的话送过去"。

它们通过 **HTTP 接口**说话，就像点外卖：你在 App 里点单（前端发请求），厨房做菜（后端处理），把菜送回来（响应）。

本项目里，后端跑在 `127.0.0.1:8000`，前端就是浏览器里那个页面。

## 2. JSON —— 两边都能读的"纸条格式"

```json
{"role": "user", "content": "你好"}
```

就是"键: 值"的文本。Python 里是 `dict`，JS 里是对象，**互换时都转成这段文本**。

后端往前端发消息、前端往后端发消息，全靠它。

## 3. 流式（streaming）—— 一边生成一边送

普通请求：后端想完 1000 字，**一次性**发给你 → 你要干等 20 秒，屏幕一片空白。

流式：后端每想出 3~5 个字就先发出来 → 你能看到字一个个"长"出来。

外卖类比：不是等整桌菜做好才上，而是**做好一道上一道**。

## 4. NDJSON —— 流式里怎么分条

流里没有"这是第一条、这是第二条"的边界。本项目的办法很土但很稳：

```
一行一个 JSON，行尾用 \n 隔开
{"message":{"content":"你"}}
{"message":{"content":"好"}}
{"__end":true,"answer":"你好"}
```

前端就按 `\n` 切开，一条条解析。**这就是为什么代码里到处是 `+ "\n"`** —— 那个换行是分隔符，不是排版。

## 5. 生成器 `yield` —— 后端的"挤牙膏"

```python
def gen():
    yield "第一段"
    yield "第二段"
```

普通函数 `return` 一次就结束；`yield` 是**挤一下停一下**，调用方拿一段、再要下一段。

后端的流式就是靠它：每想出一片字，`yield` 一次，FastAPI 就立刻把它写进网络。

> ⚠️ 新手最容易踩的坑：`yield` 只能写在函数里，而且一旦写了 `yield`，这个函数就**变成生成器**，不能再 `return 具体值`（本项目为此挂过一次服务器，见第三节末尾）。

# 第二部分 · 程序是怎么起来的（`run.py`，327 行）

打开 `run.py`，从上往下看。

## 第 1 段：开头那个 `if sys.stdout is None`

```python
if sys.stdout is None or sys.stderr is None:
    _f = open(os.path.join(_log_dir, "app.log"), "a", encoding="utf-8")
    if sys.stdout is None:
        sys.stdout = _f
```

- `sys.stdout` 就是 `print()` 往哪写。有控制台时它是一块屏幕；**没有控制台时它是 `None`**。
- 双击桌面快捷方式用的是 `pythonw.exe`（不带黑窗口），此时 `sys.stdout` 就是 `None`。
- 于是任何一句 `print("...")` 都会变成 `None.write(...)` → **直接抛异常 → 进程秒退**。
- 表现出来就是：**双击图标，窗口闪一下没了，界面也发不出消息**。

**它和谁有关：** 后端代码里有大量 `print()` 和日志（`backend/main.py`、`tools.py` 到处是）。所以这个兜底必须放在**最前面**，早于任何 import 后的执行。

> 新手理解：这不是"优雅设计"，是**被坑出来的**。注释里写的日期，就是被坑的那天。

## 第 2 段：`main()` —— 三件事（242 行起）

```python

t = threading.Thread(target=_serve, args=(server,), daemon=True)

逐行：

| 行 | 在干什么 | 为什么 |

| 262 | 创建 uvicorn 服务对象 | uvicorn 是"把 Python 函数变成网站"的工具 |
| 264 | 塞进一个**后台线程** | 因为主线程要留给窗口，不然后面 `webview.start()` 会把服务堵死 |

| 267 | `_wait_until_up()` 轮询端口 | 起服务是异步的，**必须等它真的能连上**再开窗口，否则窗口里是空白 |

## 4.1 第一道门：`send()`（约 3060 行）

```js
if (!text && imgB64.length === 0 && !videoB64) return;
if (streaming) {

**逐行：**

1. 什么内容都没有 → 直接返回（防止发空消息）。
2. 上一轮还在跑 → 判断"是真在跑还是卡死了"：超过 60 秒没有任何数据、或者连中断句柄都没了 → 认为卡死，**复位后继续发送**。

## 4.4 发请求 + 读流（约 3985 行起）

```js
buf += decoder.decode(value, { stream: true });
const lines = buf.split("\n"); buf = lines.pop();
for (const line of lines) {
  let obj; try { obj = JSON.parse(line); } catch { continue; }
  if (obj.message?.content) { answer += obj.message.content; paintAnswer(false); }
}
```

**这是流式的核心，逐行解释：**

| 行 | 在干什么 | 为什么要这么写 |
|---|---|---|
| `decoder.decode(..., {stream:true})` | 把字节流解成字符串 | 中文一个字 3 字节，**很可能被切在两片之间**；`stream:true` 让解码器记住"半个字"，下次拼上 |
| `buf.split("\n")` | 按换行切成若干条 | NDJSON：一行一条 |
| `lines.pop()` | 最后一条很可能只有半行 | **留在 `buf` 里等下一片**，不能当场解析 |
| `JSON.parse` 包在 try 里 | 解不出来就跳过 | 网络抖一下不该让整轮崩掉 |
| `answer += content` | 把碎片拼成完整正文 | 这个变量最后要交给渲染 |
| `paintAnswer(false)` | 画到屏幕上 | 传 `false` 表示"可以节流"（120ms 一次），否则每个字都重排 DOM 会卡 |

**新手常见误解：** 以为"流式 = 后端推一次，前端接一次"。实际是**上千次**，每次几个字。所以每一行都必须能容忍"断在半路"。

## 4.5 结束信号 `__end`（约 4010 行）

```js

  if (typeof obj.answer === "string" && obj.answer) {
    answer = obj.answer;      // 用服务端的整段正文覆盖
    paintAnswer(true);        // 立刻重绘一次

**它和谁有关：** 后端 `main.py` 的云端通道 `gen()` 末尾（约 6720 行）就是这个 `__end` 的生产者。

## 4.6 收尾渲染 `renderFinal()`（1196 行）

```js
function renderFinal(bubble, text, userText) {
  const raw = String(text == null ? "" : text);
  if (isPlainMode()) { bubble.textContent = raw; return; }
  try {
    if (raw.indexOf("```") >= 0) renderAnswerWithCode(bubble, raw, userText || "");
    else renderAnswerLinks(bubble, raw);
  } catch (e) { bubble.textContent = raw; return; }

  const wantTail = raw.replace(/\*\*|`|^\s*[-*]\s+/gm, "").trim().slice(-24).replace(/\s+/g, "");
  const shown = (bubble.innerText || "").replace(/\s+/g, "");
  if (wantTail && shown && !shown.includes(wantTail)) {
    bubble.textContent = raw;          // 渲染丢了结尾 → 退回纯文本
  }
}
```

**逐段：**

1. **纯文本模式**：直接 `textContent`（屏幕上就是原文，不可能少字）。
2. **格式模式**：`mdToHtml()` 把 `**粗体**`、`- 列表` 变成 HTML。
3. **末尾 24 字核对**：把原文最后 24 个字（去掉 markdown 符号）拿去屏幕上找，**找不到就说明渲染吃了尾巴** → 直接退回纯文本。

**它和谁有关：**

- `isPlainMode()`（1182 行）决定走哪条路，默认格式模式，地址栏 `?plain=1` 可切纯文本。
- `addMsg()`（1222 行）**历史消息也走这个函数** —— 早期只有实时消息走，导致"第一句完整、第二三句断"，这是真 bug。

## 5.1 本地通道 `@app.post("/api/chat")`（4308 行）

```python

**这里有个必须知道的坑：**

- 这个函数叫 `async def chat(...)`，它正常是 `return StreamingResponse(...)`（返回一个"响应对象"）。
- 但如果你在里面写 `yield`，Python 会把它**整体变成生成器**，末尾的 `return StreamingResponse(...)` 就变成语法错误：`'return' with value in async generator`。

所以上面这段用的是"**定义一个小生成器，然后 return 它**"，不是直接 yield。你以后要在这个函数里加流式输出，必须照这个写法。

# 第七部分 · 工具是怎么被真正调用的

模型说"我要读文件"≠ 文件被读。中间有一段硬逻辑，在 `backend/main.py` 的工具循环里（`chat_stream_with_tools` 返回 `tool_calls` 之后）。

```
模型输出 tool_calls（JSON）
   ↓ main.py 解析出 name + arguments
   ↓ 查表：name → 对应 tools.py 里的函数
   ↓ 调用（可能要 30 秒，比如跑代码）
   ↓ 把结果作为 role="tool" 的消息塞回对话
   ↓ 再请求模型一次，让它根据结果继续写
```

**举例：用户说"读一下 config.json"**

1. 模型返回 `{"name":"read_file","arguments":"{\"path\":\"config.json\"}"}`
2. `main.py` 调到 `tools.py` 的 `_do_read_file`
3. `tools.py` 里做**越界检查**（不许读项目根目录以外的文件）
4. 返回文件内容（可能几百行）
5. 这段内容作为工具结果回灌给模型
6. 模型看到内容后，才写出"config.json 里 default_model 是 …"

**安全边界在 `tools.py`，不在模型。** 模型说"读 /etc/passwd"，代码层会拒绝 —— 这是本项目最重要的一条设计。

# 第八部分 · 三个"看起来像 bug"的地方（新手必看）

## 8.1 下拉停在「本地·自动」，却发不出去

- `auto` 的意思不是"随便挑一个"，而是"**跟随配置里的默认模型**"。
- 昨晚我把默认模型改成了 `deepseek-flash`（云端），但 `auto` 仍然被送到 `/api/chat`（本地 Ollama）→ 拿云端模型名问本地 → 卡在"正在加载模型"。
- 现在前后端都补了判断：`auto` 指向云端模型时，自动改走 `/api/chat/deepseek`；后端也会立刻返回可读错误，不再傻等。

## 8.2 回答"最后几个字没了"

按可能性排序，**先看日志再动手**：

1. `app.log` 里 `[ds] 本轮 finish=stop 正文=N 字 尾='…'` → 后端写了多少、结尾是什么
2. Console 里 `[stream] __end local=… server=…` → 前端收到多少
3. 两个数相等但屏幕短 → **渲染层**（`renderFinal` 会自己核对并退回纯文本）
4. `local < server` → **传输层**（被掐断/超时）

> 这条排查顺序比"猜"快 10 倍，务必记住。

## 8.3 "改了代码但界面没变"

三个可能，按顺序查：

1. 窗口没重载 → 顶栏看 `v……` 版本号是否变了
2. WebView 缓存 → 现在脚本带 `?v=时间戳`，理论上不会再中
3. 改的是**后端** → 后端必须重启进程，热更无效

# 第九部分 · 动手实验（比读十遍有用）

按顺序做，每个 5 分钟：

**实验 1｜看流式到底有多碎**

在 `app.js` 的 `answer += obj.message.content;` 上面加一行：

```js
console.log("[片]", JSON.stringify(obj.message.content));
```

发一句话，打开 F12 看控制台。你会看到几十上百条，每条一两个字 —— **这就是"流式"的真面目**。

**实验 2｜让后端多发一条状态**

在 `main.py` 云端 `gen()` 里，`yield __end` 之前加：

```python
yield json.dumps({"note": "本轮共 %d 字" % len(_full)}) + "\n"
```

重启后端，发消息，右上角会弹出这条提示。

**实验 3｜故意制造一次"少字"**

把 `paintAnswer` 里的 `answerBubble.textContent = answer;` 改成 `answer.slice(0, -5)`（少最后 5 个字）。发消息 —— 你会发现最终显示其实没少，因为 `renderFinal` 的最后一道核对把它补回来了。**这一步能让你真正理解"五层兜底"为什么要叠**。

**实验 4｜读一个工具**

打开 `backend/tools.py`，搜 `def _do_read_file`，从头读到尾（大概 40 行）。看它怎么校验路径、怎么处理编码、出错返回什么格式。
