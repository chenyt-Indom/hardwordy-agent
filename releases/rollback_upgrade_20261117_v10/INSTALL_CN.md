# 全栈快照 · 回滚机制 升级包（v10）

适用：本应用的任意实例（Windows 源码版 / exe 打包版）。
**只新增文件，不修改被升级项目的任何现有文件。**

## 〇、v10 新增：exe 打包版也能回滚后端了

之前 exe 版回滚不了 `backend/` —— 后端 61 个模块被编译进 exe 的 PYZ 里，磁盘上
没有源码可还原。v10 的做法是：**把 exe 本身也存一份，换 exe 就等于换后端**。

| 项 | 说明 |
|---|---|
| 快照里存 exe | 打包版建快照时，当前 exe 按 sha256 存入 `data/rescue_snapshots/_exe_pool/` |
| 不塞进 zip | exe 放独立池子、按 sha256 去重：同一版 exe 只存 1 份，快照 zip 仍是几十 KB |
| 版本数 | exe 池保留 5 个版本（约 225MB）；**正被快照引用的那份绝不会被清理** |
| 回滚时 | 代码还原后，若 exe 与快照不同 → 一并换回；exe 一样则跳过（不白拷 45MB） |
| 应用正在运行 | Windows 不许覆盖运行中的 exe → 自动留 `<exe>.new` 并生成 `_swap_exe.bat`：**关掉应用就自动替换并重启**；也可双击那个 bat 立刻完成 |

代价：每多一个不同的 exe 版本多占约 45MB（同一版不重复占）。快照列表里带
「含 exe」标记的就是能连后端一起回滚的那份。

## 〇之二、v5 相对 v4 修了什么

| 修复 | 影响 |
|---|---|
| **缺 manifest 直接拒绝** | 以前把快照 zip 里的 `_manifest.json` 删掉，回滚仍判「成功」——因为完整性核对会退回用「zip 条目自身大小」比对，等于自己跟自己比，永远通过。现在缺清单一律拒绝（fail-closed） |
| **快照残缺会明说** | 以前某个文件被别的程序独占/读不了时，快照悄悄少一个文件却照样 `ok=True + healthy=True`。现在返回 `skipped` / `incomplete`，缺的若是源码（backend/frontend/launcher）直接标 `healthy=False`，自动回滚会跳过它 |
| 空快照提示更准 | 空 zip 现在报「这个快照是空的」，而不是含糊的「缺 manifest」 |

老快照兼容：`sizes`/`hashes` 字段引入之前建的快照仍能正常回滚，不会被误拒。

## 一、包里有什么

| 文件 | 作用 |
|---|---|
| `rescue.py` | 快照 / 回滚引擎（纯标准库，不 import backend） |
| `rollback_console.py` | 浏览器控制台（独立运行，不改对方前端/后端） |
| `start_console.bat` | 双击启动控制台 |
| `INSTALL_CN.md` | 本说明 |

## 二、安装（三步）

1. 把 `rescue.py` 和 `rollback_console.py` 复制到**对方项目的根目录**
   - 源码版：有 `backend/` 和 `frontend/` 的那一层（通常是 `run.py` 所在目录）
   - **exe 打包版：和 `本地多模态助手.exe` 放在同一层**
2. 双击 `start_console.bat`（或 `python rollback_console.py`）
3. 浏览器自动打开 `http://127.0.0.1:8123`，看到「全栈快照 · 回滚控制台」即安装成功

> 不需要改 `main.py`、`app.js`、启动脚本；不需要装任何第三方库；不需要 git。
> 需要对方机器装有 Python 3（exe 版如果没装 Python，用下面的命令行方式让主程序调）。

## 三、怎么用

- **＋ 立即快照**：给当前状态存一份（会弹框让你起名字），手动快照独立保留 5 个
- **回滚**：点任意一行右侧的按钮，回到那个版本。回滚前会自动把当前状态存成
  「回滚前备份」，点它就能退回来
- **⟲ 回滚到最近健康版**：从新到旧逐个试，起不来的自动跳过

## 四、命令行用法（不开界面也行）

```
python rescue.py --snapshot --tag "改代码前"  # 建快照
python rescue.py --list                      # 列出快照
python rescue.py --precheck                  # 只检查代码能否 import
python rescue.py --deep-check                # 真起一次服务验证（临时端口 8011）
python rescue.py --rollback --snap <文件名>   # 回滚到指定快照（加 --force 可强制）
python rescue.py --auto                      # 自动回滚到最近健康版
python rescue.py --health                    # 查主程序健康状态
python rescue.py --clean-snapshots           # 按配额清理旧快照
```

## 五、源码版 vs 打包版（重要区别）

| | 源码版 | exe 打包版 |
|---|---|---|
| 快照文件数 | 约 180+ | 约 17（前端 15 + 引擎） |
| 能回滚前端 / 配置 / data 状态 | ✅ | ✅ |
| 能回滚 `backend/` 后端代码 | ✅ 直接还原 61 个 .py | ✅ **通过换 exe 还原**（v10 起；exe 版本池保留 5 个） |
| 回滚后的验证方式 | 真跑 `import backend.main` | 文件完整性检查 |

exe 版回滚后端的原理是「换回旧 exe」，所以：

1. 只有**带「含 exe」标记**的快照才能连后端一起回滚；
2. 应用正在运行时 exe 换不了，会生成 `_swap_exe.bat`，**关掉应用即自动完成**；
3. 若那份 exe 已被清理（超出 5 个版本），会明确提示「代码已回滚，exe 需重新安装」。

## 六、快照里有什么

**包含**：`backend/`、`frontend/`、`launcher/` 下的源码，根目录的 py/bat/json/md，
以及 `data/` 下的状态文件（技能、定时任务、自迭代计划等）。

**不包含**（有意排除）：
- `secrets.json` —— 回滚旧密钥会让当前可用的 API 直接失效
- `models/` 模型权重、`sessions/` 聊天记录、图片与媒体缓存

保留策略：自动快照 8 个、回滚前备份 2 个、手动快照 5 个，超出按时间从旧到新清理。
打包版另有 **exe 版本池 5 个**（按 sha256 去重，被快照引用的不清理）。

## 七、注意事项

1. **回滚会把 `data/` 状态一起退回快照时刻**，快照之后新建的技能/定时任务会消失。
2. 回滚后**必须重启主程序**才生效。exe 版若提示「exe 已就绪」，
   **关掉应用就会自动替换并重启**（`_swap_exe.bat` 在等它退出）。
3. 主程序正在正常运行（8000 端口通）时，控制台回滚会带 `force` 强制放行；
   若担心，先关掉主程序再回滚。
4. 程序彻底起不来、连控制台都打不开时，用命令行 `python rescue.py --auto` 兜底
   （它只依赖标准库，不依赖主程序）。
5. 首次使用**没有任何快照**，请先点「＋ 立即快照」建一个基线，否则没东西可回滚。
6. 快照文件可以拷走备份，但**别从不可信来源导入 zip**（虽然已做 Zip Slip 防护，
   但被篡改的快照仍会被判为不可信并拒绝回滚）。

## v3 新增的安全保护（2026-11-17）

| 保护 | 说明 |
|---|---|
| 空快照拒绝 | 快照里 0 个文件时直接拒绝回滚，避免把 backend/ frontend/ 清空 |
| 大量删除拒绝 | 回滚会删掉超过一半源码时拒绝（确要执行加 `--allow-mass-delete`） |
| 快照截断检测 | manifest 记录每个文件真实大小，恢复出来的文件明显偏小则判失败并自动退回 |
| 建快照自检 | 建完立刻回读 zip 核对每个条目大小，不一致就删掉这份废快照 |
| 并发安全 | 快照文件名用原子占位，多线程/多进程同时建快照不会互相覆盖 |
| 校验防假阳性 | 导入后断言模块真的来自本项目，避免 PYTHONPATH 干扰导致「假成功」 |

## v8 修复（2026-11-17 23:33）

本版修掉 3 个问题，其中前两个是「会让回滚莫名其妙被卡住」的：

1. **锁文件残留会锁死回滚 180 秒**
   `_acquire_lock()` 返回 `(fd, interrupted)` 元组，`_release_lock()` 只收单个 fd。
   万一有人误写成 `_release_lock(_acquire_lock())`，`os.close(元组)` 抛异常被吞 →
   句柄没关 → Windows 上删不掉锁文件 → 锁里记的是本进程 pid、进程活着、又没超
   180 秒 → 之后建快照和回滚全被拒，提示「另一个回滚正在进行」，实际没人在回滚。
   现在：① 收到元组自动解包；② 关闭句柄失败记日志；③ 删除重试 5 次；
   ④ 新增判定「pid 是自己 且 本进程没有持锁线程 → 必然是残留，立即接管」，
   不再干等 180 秒（实测接管耗时 0.01 秒）。

2. **0 字节残留文件永久累积**
   建快照用 `O_CREAT|O_EXCL` 原子占名，占完名才开始写。若中途进程被强杀，
   会留下 0 字节 .zip；而列表会主动跳过 0 字节文件（不显示写了一半的中间态），
   于是它永远进不了清理队列。实测造 20 个残留 + 建 12 个快照触发 4 轮清理，
   一个都没被删。现在每次清理会顺带删掉「0 字节 且 mtime 超过 10 分钟」的残留，
   正在写入的文件（新鲜的 0 字节）不会被动。

3. **快照名前缀有歧义时会静默回滚到别的版本**
   原先 `_resolve_snap()` 用 `startswith` 第一个命中就返回。两个快照共享前缀时
   （比如 `--snap snap_`），会滚到任意一个，用户以为滚的是自己点的那份。
   现在：精确名优先；前缀只在唯一命中时使用；多个命中直接报错，不猜。

另外 CLI 的 `--list` 文案统一：`bad_` 显示「回滚前备份」（原来显示「未知/坏」，
容易让人以为代码坏了，其实那正是回滚前的正常版本）。

## v9 变更（2026-11-17 23:37）

1. **快照目录建不出来时明确报错**：`data` 被同名文件占住/权限不足时，
   原来会抛未捕获的 `NotADirectoryError`（前端收到 500），现在返回清晰原因。
2. **拒绝用其他项目的快照回滚**：每个项目有稳定标识 `data/project_id`，
   从别的项目拷来的快照会被拒绝（提示项目标识不一致），
   避免用别人的代码覆盖本项目。确认要强制恢复可加 `--allow-foreign`。
   - 项目移动/改名/换目录**不受影响**（标识跟着 `data/` 一起走，不会变）；
   - 老快照没有该字段，按「无法判定」放行，历史快照不会失效。
